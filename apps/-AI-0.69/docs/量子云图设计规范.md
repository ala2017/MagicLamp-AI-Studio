# 量子云图设计需求规范（完整版）

## 功能概述
```
量子云图是一个高级书签可视化工具，它将用户的书签层级结构以数据可视化的的形式展现，使用户能够直观地查看、导航和管理其完整的书签体系。通过将传统的树状书签结构转换为动态的、可交互的网络图，量子云图提供了一种全新的书签导航体验。
```

## 一、基础信息

### 1.1 功能定位与入口
```
功能名称: 量子云图
功能入口：AI辅助功能页面（ai空间）左侧量子云图按钮
显示区域：content-placeholder
```

### 1.2 文件结构
```
src/
└── pages/
    └── ai-space/
        └── cloud-map/      # 量子云图
            ├── cloud-map.html

            └── cloud-map.css
```

## 二、数据处理

### 2.1 数据来源
```
利用浏览器 API 获取用户收藏夹数据，解析书签的层级结构信息（如文件夹名称、书签标题、URL）。
考虑数据更新时的动态刷新机制，确保展示的数据与用户收藏夹保持同步。
```

### 2.2 数据转换
```
将原始数据转换成适合可视化组件处理的数据格式（例如 JSON 树状结构）。
```

## 三、视觉设计系统

### 3.1 整体布局
```
显示效果要求，在显示区域内根据内容，均匀，平衡的填充，并保持节点之间不遮挡，动态间距。
当节点展开时，遵从子节点基于父节点同心圆的方式均匀分布
采用酷炫的动画效果，如节点渐入、平滑过渡、缩放、旋转等。
```

### 3.2 节点设计与层级结构
```
- 以"书签栏"为核心中心节点
- 第一层子节点呈现径向分布
- 默认展开深度为1层(即中心节点及其直接子节点)
- 节点大小：
  - 中心节点（书签栏）：30px
  - 文件夹节点：20px
  - 书签节点：20px
- 节点间距：
  - 中心节点到第一层子节点：120px
  - 子节点之间的最小间距：40px
  - 更深层级的节点分布半径：200px
```

### 3.2.1 默认显示状态
```
- 初始状态以"书签栏"为核心中心节点
- 默认显示1层深度：中心节点(书签栏)和一级子节点(直接子文件夹及书签)
- 文件夹节点直接显示其名称
- 书签节点使用图标方式呈现，图标背景透明度设置为99%
- 书签节点不显示名称，仅在交互时展示
```

### 3.3 颜色系统
```
颜色继承规则：
1. 书签栏（中心节点）的子文件夹使用不同的颜色，不继承书签栏的颜色
2. 书签栏以外的文件夹，其子文件夹和连接线继承父级文件夹的颜色
3. 书签节点统一使用 #999 颜色

3.3.1 颜色生成系统
1. 基础颜色集（16色）
const baseColors = [
    '#FF1744', // 鲜红色
    '#FF5252', // 亮红色
    '#FF4081', // 粉红色
    '#F06292', // 浅粉色
    '#9C27B0', // 紫色
    '#673AB7', // 深紫色
    '#3F51B5', // 靛蓝色
    '#2196F3', // 蓝色
    '#00BCD4', // 青色
    '#009688', // 蓝绿色
    '#4CAF50', // 绿色
    '#8BC34A', // 浅绿色
    '#CDDC39', // 酸橙色
    '#FFEB3B', // 黄色
    '#FFC107', // 琥珀色
    '#FF9800'  // 橙色
];

2. 颜色变体生成规则
基于16种基础颜色，通过以下规则生成至少500种颜色变体：

a) 亮度变体生成：
   - 范围：30% - 70%
   - 步长：10%
   - 条件：与原始颜色亮度差异>5%

b) 饱和度变体生成：
   - 范围：60% - 100%
   - 步长：10%
   - 条件：与原始颜色饱和度差异>5%

c) 色相变体生成：
   - 偏移量：±5°, ±10°, ±15°, ±20°, ±25°
   - 对每个基础颜色生成10个色相变体

d) 组合变体生成：
   - 色相偏移：±15°
   - 饱和度偏移：±10%
   - 亮度偏移：±10%
   - 确保新生成的颜色与现有颜色有足够差异

e) 补充规则：
   - 如果生成的颜色数量不足500个，通过微调色相（1-4度）继续生成
   - 新生成的颜色需要与现有颜色有视觉上的可区分度
   - 所有颜色都应保持在可读性范围内

3. 颜色应用规则
a) 节点颜色分配：
   - 书签栏节点：使用默认主题色
   - 书签栏的直接子文件夹：从500种颜色库中选择不同颜色
   - 其他文件夹节点：继承父文件夹的颜色
   - 书签节点：统一使用 #999

b) 连接线颜色：
   - 继承源节点颜色
   - 透明度：0.6
   - 宽度：2px

c) 颜色选择策略：
   - 相邻节点使用差异明显的颜色
   - 确保颜色对比度满足可访问性标准
   - 避免使用过于相似的颜色组合
```

### 3.4 连接线样式
```
1. 线条设计：2px宽度，半透明（opacity: 0.6）
2. 颜色继承：连接线颜色必须与源节点颜色一致
3. 交互状态：悬停时提高透明度至0.8，宽度增加至2.5px
4. 动画过渡：所有变化都应有平滑过渡（transition: all 0.3s ease）
5. 父子节点连接线用直线
```

## 四、交互设计

### 4.1 基础交互
```
支持拖拽节点重新排列、放大缩小操作，保证操作过程中视觉流畅无卡顿。
提供层级展开/折叠功能，用户能动态查看不同层级的书签目录。
响应式布局，适配不同屏幕尺寸和浏览器窗口调整。
默认显示1层深度（中心节点及其直接子节点），如文件夹同级有书签，只显示书签图标，鼠标悬停时显示书签名称。
```

### 4.2 点击文件夹节点的交互机制
```
1. 点击文件夹节点时，要保持节点间的相对位置关系
   - 点击前：当前文件夹处于折叠状态，只显示该节点
   - 点击后：子节点从父节点位置平滑展开，呈放射状分布

2. 视觉过渡效果
   - 展开动画：节点从父节点位置向外扩散
   - 连接线动画：从父节点延伸出连接线
   - 状态变化：父节点颜色或大小微妙变化，表示已展开

3. 布局稳定性
   - 展开时其他节点的位置应保持相对稳定
   - 避免布局突然跳变或重新计算
   - 使用力导向算法时，控制力的参数，确保展开/折叠平滑不剧烈

4. 多层级处理
   - 默认情况下展开一层（中心节点及其直接子节点）
   - 点击深层文件夹时，展开其子节点，同时保持其他已展开的节点状态
```

### 4.3 悬停交互
```
1. 节点悬停效果：
   - 节点放大约20%
   - 亮度提高（filter: brightness(1.2)）
   - 显示完整标题信息

2. 连接线悬停效果：
   - 线条透明度提高
   - 线条宽度增加
   - 平滑过渡动画
   
3. 书签节点悬停效果：
   - 当鼠标悬浮在书签图标上时，在图标右侧显示书签名称
   - 名称显示使用文本提示框，背景半透明
   - 提示框位置固定在图标右侧，避免遮挡其他节点
   - 显示与隐藏过程使用淡入淡出动画（0.2s）
```

### 4.4 拖拽交互
```
1. 拖拽开始：
   - 节点位置固定（fx, fy）
   - 模拟重启，增加活力因子

2. 拖拽中：
   - 节点随鼠标移动
   - 连接的线条实时更新
   - 其他节点做出相应调整

3. 拖拽结束：
   - 如设计为放手后固定，则保持位置
   - 如设计为放手后自由，则释放固定位置
   - 力导向图重新计算布局，但保持相对位置关系
```

## 五、控制面板设计

### 5.1 面板布局
```
控制面板位于右上角，半透明效果，鼠标悬停时变为不透明
分组展示不同类型的控制选项
```

### 5.2 功能按钮
```
1. 视图控制：
   - 重置视图：恢复默认视图状态
   - 展开全部：展开所有可见节点
   - 折叠全部：折叠到默认状态

2. 刷新功能：
   - 刷新数据：重新加载书签数据
   - 视觉反馈：加载动画显示

3. 布局控制：
   - 布局模式切换：力导向/径向布局
   - 节点间距调整：通过滑块控制
```

## 六、性能优化策略

### 6.1 渲染性能
```
采用虚拟DOM或局部更新策略，避免大量DOM重绘造成卡顿。
异步数据加载与懒加载处理，提升首次加载速度与交互响应速度。
```

### 6.2 具体优化措施
```
1. 仅渲染可见节点：
   - 使用updateNodeVisibility函数管理可见性
   - 隐藏折叠节点的子节点

2. 缓存优化：
   - 使用colorMap缓存颜色映射
   - 使用nodePositions记录节点位置
   - 图标缓存避免重复加载

3. 力导向优化：
   - 精心调整力参数，确保大量节点时的表现
   - 使用碰撞检测避免节点重叠
   - 适当降低非活动状态的更新频率
```

## 七、错误处理与用户反馈

### 7.1 错误处理机制
```
try-catch包裹所有关键操作
异步操作错误捕获并显示用户友好信息
数据加载失败时显示重试选项
```

### 7.2 加载状态
```
使用加载动画显示进度
主要操作（如初始化、展开大型目录）时显示状态提示
长时间操作提供取消选项
```

## 八、开发与维护规则

### 8.1 修改前检查清单
```
1. 代码修改前必须检查所有受影响的核心设计决策
2. 明确标出修改可能影响的其他功能点
3. 确保新代码遵循所有已确认的设计要求
4. 特别检查与颜色继承、节点交互相关的核心功能
```

### 8.2 模块化修改策略
```
1. 将大的修改分解成独立的小改动
2. 每个小改动只针对一个具体问题
3. 避免"大爆炸"式的代码重写
4. 关键功能保持隔离，避免连锁影响
```

### 8.3 前后对比验证
```
1. 每次修改后，明确列出"修改前存在的问题"和"修改后可能影响的功能"
2. 确认修改不会破坏其他功能
3. 特别关注颜色继承、节点交互等核心功能
4. 使用版本对比确认变更范围在预期内
```

### 8.4 知识库管理
```
1. 结构化存储设计决策：
   - 按功能模块分类（视觉/交互/数据/性能等）
   - 保留原始描述，不进行改写
   - 为关键决策添加索引和标记

2. 双轨工作模式：
   - 保留完整的原始需求记录
   - 维护当前开发参考文档
   - 确保两者保持同步

3. 增量式记录：
   - 每次讨论后直接添加新内容到分类库
   - 不尝试重新总结全部内容
   - 使用明确的版本标记
```

### 8.5 搜索与引用策略
```
1. 在提出修改方案时，直接引用之前的对话内容
2. 不依赖"记忆"或"总结"过去的决策
3. 关键部分使用原文引用
4. 使用精确关键词搜索相关决策
5. 验证搜索结果包含所有关键决策
```
