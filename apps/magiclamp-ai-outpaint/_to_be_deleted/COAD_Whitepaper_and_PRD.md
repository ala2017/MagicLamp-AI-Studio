# COAD: 契约式 AI 编程框架
**(Contract-Oriented Autonomous Development)**

> **副标题：** 终结 Agent“鬼打墙”与“代码幻觉”的下一代工程纪律白皮书 & 产品需求文档 (PRD)
> **发起人：** 神灯AI Lab
> **版本：** v1.0 (2026-05)

## 第一部分：白皮书 (The White Paper)

### 1. 行业背景与“智能陷阱”的诞生
随着 Claude Code、OpenHands 以及各种商业化 AI IDE（如 Cursor, Windsurf）的普及，软件开发正式进入了 Agent 时代。然而，工业界的真实体验并未达到“全自动开发”的预期，反而陷入了深度的“维护地狱”。

当剥开大模型看似聪明的伪装，我们会发现当前所有 AI 编程工具都面临着难以逾越的四大“智能陷阱”：

#### 痛点 1：记忆毒化与逻辑死锁（“鬼打墙”）
*   **现象**：AI 尝试修复 BUG 失败后，会将错误的推导逻辑和污染的代码写入上下文记忆。随后的多轮对话中，AI 陷入“补丁打补丁”的惯性思维（Tunnel Vision），在死胡同里越钻越深。
*   **根本原因**：当前的“长上下文”机制是单向堆叠的黑盒，缺乏显式的记忆阻断和回滚能力。

#### 痛点 2：目标逃避与隐性阉割（“掩耳盗铃”）
*   **现象**：为了在沙盒中让代码能够跑通、不报红，AI 会隐蔽地删减用户原定的核心复杂需求。表面上提示“Bug 已修复”，实则是把功能阉割了。
*   **根本原因**：模型被训练为倾向于给出“积极、成功”的反馈（Sycophancy），缺乏严苛的第三方结果审计。

#### 痛点 3：盲目执行与经验断层（“闭门造车”）
*   **现象**：面对框架的底层报错（如显存溢出、冷门库的兼容 BUG），AI 倾向于盲目瞎猜底层参数或提供过时的 Hack 方案，而不主动查阅社区的最新最佳实践。
*   **根本原因**：工具未能在编写代码前建立“强制调研”的生命周期。

#### 痛点 4：工程熵增与基建塌方（“只管拉屎不管擦屁股”）
*   **现象**：AI 极大地加速了代码生成，但配套的文档、架构图、Changelog 完全脱节。项目迭代 3 个版本后，成为除了大模型以外无人能看懂的“赛博屎山”。
*   **根本原因**：缺乏自动化的生命周期收尾机制。

### 2. COAD 核心方法论 (The Methodology)
面对上述陷阱，COAD（契约式自治开发）主张：**在 Agent 时代，工程纪律（Discipline）远比模型本身的智能（Intelligence）更重要。**
系统需要一个“纪律执行官”，严格按照以下四大原则约束 AI：

1.  **第一原则：PRD 驱动约束 (PRD-Driven Constraint)**
    *   彻底废弃“随口提需求”。项目必须基于结构化的 PRD 推进，代码产出必须由独立的 Validator 根据 PRD 进行逆向校验。
2.  **第二原则：降维熔断机制 (Stop-Loss & Dimensionality Reduction)**
    *   赋予系统“认怂”的能力。设定明确的死锁阈值（如针对同一文件连续修改 3 次失败），触发后强制切断污染上下文，回滚代码，并强迫模型切换解决维度（如：从算法优化切换为降级硬编码）。
3.  **第三原则：先验挂载引擎 (Pre-flight RAG)**
    *   在动手写代码前，强制截断冲动。遇到疑难杂症，必须优先触发社区 / Web 搜索，带着最新最佳实践进入 Coding 阶段。
4.  **第四原则：生命周期强制闭环 (Mandatory Lifecycle Closing)**
    *   任何一个 Feature 分支合并前，必须自动完成：双向同步文档、脱敏隐私 Key、生成专业 Git Commit 记录。

## 第二部分：产品需求文档 (PRD)

### 1. 产品定位
**“面向复杂工程的 AI 技术主理人 (AI Tech Lead Engine)”**
本产品不是取代 Cursor 的 IDE，而是一个极轻量级的、隐形的 **命令行守护进程 (CLI Daemon) + 本地插件**。它挂载于开发者的任意项目中，充当“包工头”与“质检员”，专门负责鞭策底层的大模型（打工仔）。

### 2. 系统架构与核心模块

#### 2.1 基础架构：`.lamp` 契约目录
用户在项目根目录运行 `lamp init`，系统生成受版本控制的隐形枢纽：
*   `.lamp/PRD.md`：核心需求契约。
*   `.lamp/RULES.md`：全局止损规则与框架规范。
*   `.lamp/tree/`：存放微观的快照状态，用于记忆重置。

#### 2.2 模块 A：契约守护犬 (Contract Watchdog)
*   **功能描述**：双模型对弈机制。当 Coding Agent 完成代码修改后，系统在后台隐蔽唤醒独立的 Review Agent（通常使用成本极低的极速模型即可）。
*   **执行逻辑**：
    1. Review Agent 读取 `.lamp/PRD.md`。
    2. 对比 Diff，判定是否存在“为了跑通代码而删除原有需求”的行为。
    3. 如果存在，直接触发拦截警告，并强令 Coding Agent 返工。

#### 2.3 模块 B：记忆分支树与熔断器 (Memory Breaker)
*   **功能描述**：终结“鬼打墙”的最强武器。
*   **执行逻辑**：
    1. **隐性快照**：AI 每修改一次文件，系统都在后台建立一个无头 Git Commit（隐性快照）。
    2. **自动熔断**：当模型在同一个方法或 BUG 上盘旋超过 3 个回合，抛出警告：`[System] 检测到逻辑死锁！`。
    3. **手动指令 `lamp reset`**：开发者只需一键，系统自动回滚代码到 3 步前的状态，并在大模型的上下文中强力注入一剂“失忆药水”与“反省指令”（例如：“前置思路已被验证不可行，你必须提出两种完全不同的替代架构方案，不准再纠结于之前的 CSS 属性”）。

#### 2.4 模块 C：先验检索钩子 (Pre-flight Scanner)
*   **功能描述**：遇到核心异常时强制补课。
*   **执行逻辑**：捕获到 Terminal 报错包含 `CUDA Out of Memory`、`Segmentation Fault` 或未知的框架级 Error 时，拦截模型直接出代码的动作，自动调用 `Search Web` 挂载对应的官方文档 and GitHub Issues，总结成熟方案后再放行编码。

#### 2.5 模块 D：收尾流水线 (Closing Pipeline)
*   **功能描述**：自动化的工程基建。
*   **执行逻辑**：当一个功能被开发者标记为验收通过（`lamp done`），系统在后台并行执行：
    1. 扫描并替换代码库中的隐私 Token（脱敏）。
    2. 依据 Diff 自动在 `CHANGELOG.md` 中以规范格式增加条目。
    3. 同步打钩或修改 `.lamp/PRD.md` 中的进度。
    4. 执行最终的 `git commit -m` 及远端推送。
