## 1. 产品定位与核心目标

神灯AI · Outpaint v2 是一款**专为高精度电商、服装、壁纸设计商户量身定制的 SaaS 级智能扩图与画面擦除工作台**。

在 v1 阶段验证了 16GB 显卡运行可行性的基础上，v2 通过**双推理管线架构（标准 Paste-Back 与高清 Crop-and-Stitch）**以及**几何投影纠偏技术**，实现了“扩图主体 0 损失、大图拼接无缝隙、消除修补秒响应”的极高画质保障。同时在前端交互上融入了流光预载、磨砂锁定等 SaaS 级生命周期闭环，旨在为非技术商户提供最丝滑、最专业的设计生产力。

## 2. 核心功能管线规格 (The Two Core Pipelines)

系统会自动根据上传原图的尺寸与边界关系，智能分流至不同的处理管线：

### 2.1 管线 A：标准 Paste-Back 扩图管线 (原图长边 ≤ 720px)
针对中低分辨率图片，通过整体下采样推理并超清放大，再无损拼接回贴，在保证背景构图一致性的同时节省时间。

*   **流程图解**：
    `原图缩放 -> 1280x720 整体画布 -> FLUX.1 Fill 推理 -> RealESRGAN 4x 超分 -> 原始原图无损 Paste-Back (12px 边缘羽化覆盖)`
*   **输入规格**：原图最大长边不超过 720 像素。
*   **技术规格**：
    1.  **降维防复制**：FLUX 推理限制在 `1280x720` (0.92 Megapixel)，遵守 1 Megapixel 防幻觉最佳实践，100% 杜绝在盲目高分辨率下产生“多头/复制人”或断层幻觉。
    2.  **Paste-Back 物理覆盖**：由 RealESRGAN 将生图结果放大至 5120x2880。接着，前端传入的 0~1 归一化坐标经后端还原为确切的像素包围盒，将高解析度原图（不经过降采样降质）直接贴回超分画布。
    3.  **边缘羽化过渡**：使用距离变换函数（EDT）在原图边缘 12px 范围内产生自适应 Alpha 渐变 mask，实现原图与 AI 生成背景的无缝融合。

### 2.2 管线 B：Crop-and-Stitch 高清分块扩图管线 (原图长边 > 720px)
针对高分辨率大图（如 4K 级别图片），若直接强制缩放会导致主体变糊。管线 B 采取“局部裁剪推理、全局动态缝合”的领先技术。

*   **流程图解**：
    `原图尺寸检测 -> 留白边缘条带分析与切割 -> 带上下文条带独立 FLUX 推理 -> 缝合拼接至主画布 -> 整体超分 -> 原始大图物理 Paste-Back (16px 边缘羽化)`
*   **触发条件**：原图最大长边大于 720 像素。
*   **技术规格**：
    1.  **留白条带切割**：检测图片拖拽后在画布中暴露的“上、下、左、右”留白缝隙。只切割需要生成背景的“空白窄条带”，并向下兼容延伸 **30% 的原图边缘作为上下文信息**送入模型。
    2.  **动态分辨率推理**：将条带单独缩放到 FLUX 兼容尺寸（长边≤1280，对齐 16 的倍数）进行高有效分辨率推理。因为只生边缘，**AI 扩图的有效清晰度较传统缩放提升了 3~5 倍**。
    3.  **方向性羽化缝合 (`stitch_strip`)**：生图条带尺寸还原后，在与原图接壤处实施 **50px 软过渡羽化**，而其外部（空气扩展边缘）保持 100% 不透明度。四边分别缝合，合成为一张高清基底大图。
    4.  **大图超分与高清晰度贴回**：对缝合画布进行 2x 或 4x 独立超分，随后将最完整、未经任何降质的超清原图贴回。

## 3. 图像预处理规格 (消除与重绘)

前端工作台配备“消除画笔”工具，用于去除画面中的无关物品、路人或水印瑕疵：

### 3.1 离线 OpenCV 极速擦除 (`fast_erase`)
专为秒级消除高频操作设计的传统 CV 方案，**完全不占用显存**，可在冷启动期间 100% 畅通使用。

*   **几何投影纠偏 (Hires Projection)**：
    前端 Fabric 画布（1280x720）上产生的涂抹路径（Path）在导出时，系统自动隐藏非相关层，利用 `getBoundingRect` 包围盒将画笔笔画高精度映射拉伸至与原始高清原图 **1:1 绝对对齐的临时 Canvas 上导出**。解决旧版几何偏差错乱导致擦除无效的 Bug。
*   **自适应动态边缘膨胀**：
    后端使用二进制膨胀法（`binary_dilation`）自动根据原图长边分辨率动态计算膨胀迭代次数（3次至15次），以彻底盖住涂抹边缘由抗锯齿带来的半透明灰色残留，通过 **OpenCV Telea 修复算法**进行毫秒级弥合补全。

### 3.2 AI 局部重绘 (FLUX Inpaint)
针对大面积、复杂纹理的擦除修补需求，调用深度模型进行智能联想补全。

*   **规格指标**：
    1.  图片与投影纠偏掩膜（Mask）均缩放至 1280 级尺寸，并配合 `gaussian_filter` 进行 3px 膨胀与高斯轻度羽化。
    2.  **20步精细去噪**：调用 FLUX.1 Fill 推理，步数设为 20（速度与质量的甜点期），引导强度 30.0。
    3.  **Prompt 策略**：去水印调用“clean background, no watermark...”；通用消除调用“fill with surrounding background...”，完美融入场景。

## 4. 交互体验与 SaaS 级生命周期 (UX Specs)

系统遵循**“防止盲目乱点 -> 智能状态反馈 -> 动态生命周期闭环”**的设计原则：

### 4.1 导入前物理约束与首道防线
*   **画布物理约束（防丢防坏）**：
    1.  **撞墙保护**：移动图片时，必须保证至少 50% 的面积在画布可见范围内，否则执行Offset-based钳位边缘防抖动回弹，防止图片被拖飞。
    2.  **缩放约束**：限制图片在画布比例下的缩放极限在 50% 至 300% 之间，防止过小或过大。
*   **无图物理拦截**：
    在未导入图片时，若鼠标在 Fabric 画板上拖拽绘图，系统将首道拦截，利用 Fabric 的 `path:created` 机制自动删除该脏路径，并以控制台警示：“请先导入图片以点亮画布”。

### 4.2 大模型冷启动物理加载屏障 (#system-loading-gate)
FLUX 大模型首次载入分配显存需 1~3 分钟。
*   **前置加载遮罩**：未检测到模型就绪时，全屏置入毛玻璃流光遮罩。
*   **显存心跳同步**：前端 `app.js` 启动 `startModelStatusCheck()` 主动心跳，高频轮询 `/api/health`。从后端实时读取显卡型号（如 RTX 4060 Ti 16GB）以及**可用显存比例，并按 20%~95% 的比例拉伸预载进度条**，提供极具科技流光的视觉回馈。
*   **锁闭解除**：大模型就绪后，进度条瞬间满格，遮罩面板以 `scale(1.0) -> scale(1.08)` 和 `opacity -> 0` 的动画平滑淡出，解锁工作台。若后端离线，屏障自动拉红报警。

### 4.3 右侧精细参数卡片生命周期锁定 (#right-panel-mask)
*   **初始锁定态**：右侧画笔尺寸、推理步数、引导参数滑块以及“生成壁纸”按钮上方覆盖磨砂锁定层，呈不可操作状态。
*   **导入点亮态**：在 `handleFile` 导入图片事件成功后，自动添加 `.hidden` 类消除磨砂锁，允许调节参数。
*   **清空重锁态**：当点击“清空重置”时，重新去除 `.hidden` 类上锁右侧，达成完美的生命周期闭环。

## 6. 社区成熟开源方案技术参考与高频低级交互改良指南

在当前版本的实际操作中，存在若干阻碍工作流、严重降低生产力效率的**低级交互硬伤**。本章节立足于第一性原理，结合社区最成熟的开源方案（如 AUTOMATIC1111 WebUI、ComfyUI 核心画板及 Figma 交互逻辑），指出当前设计的缺陷，并为后续版本的改良设计提供具备极高落地性的技术规格。

### 6.1 当前版本三大低级交互缺陷诊断

#### 🚫 【硬伤一】“涂抹一次即强制弹回选择模式”的低级逻辑
*   **现象**：用户在点击“画笔消除”按钮涂抹一笔并松开鼠标后，前端系统会自动且强制地将画布状态恢复为默认的“选择/拖动模式”。如果用户需要连续消除画面中的多个不同小物体（如分布在各处的文字或水印），必须点一下画笔 -> 涂抹一处 -> 再去右侧点一下画笔 -> 涂抹第二处，体验极其繁琐。
*   **原因分析**：旧的设计过度防范了由于保持画笔状态可能导致的画布误触问题，在涂抹事件（`path:created`）的回调函数尾部暴力执行了类似 `setMode('select')` 的重置逻辑。
*   **后果**：严重割裂了连续涂抹的工作流，对高频擦除消除操作产生了反人类的点击负担。

#### 🚫 【硬伤二】“掩膜笔迹允许被误触、点选并拖走”的图层混杂
*   **现象**：在选择模式下，鼠标如果不小心点中了刚刚涂抹的红色笔画，该笔画路径（Path 对象）会被当成普通图形一样被框选、拉伸甚至拖拽位移。这会导致导出的 Mask 区域与图片中的实体像素发生偏差，擦除失败或将不该消除的像素擦掉。
*   **原因分析**：没有对 Fabric.js 的渲染图层对象进行物理/属性上的锁死，将用作渲染掩膜的临时笔迹与作为操作主体的图片混在同一层级内进行统一事件响应。
*   **后果**：经常性发生“误触把掩膜拖跑了”的低级错误，导致商户极为迷惑且极易导致推理区域漂移。

#### 🚫 【硬伤三】“缺乏笔迹高精度撤销（Undo/Redo）与容错”
*   **现象**：用户涂抹掩膜时，一旦有某一边缘画错了，目前没有任何办法进行“撤销这一笔”的操作。用户只能选择要么点击“清空重置”将所有辛苦画好的遮罩全部擦除重来，要么忍受瑕疵，容错率极低。
*   **原因分析**：前端缺乏对 Fabric.js 路径生成的历史队列管理，没有建立基于画笔笔画的历史回溯栈（Stroke History Stack）。

### 6.2 社区成熟开源方案与交互范式技术参考

#### 1️⃣ AUTOMATIC1111 / ComfyUI Mask Editor (掩膜隔离与锁定范式)
*   **参考规格**：
    A1111 与 ComfyUI 的内置 Inpaint 遮罩涂抹工具中，涂抹的 Mask 绝不会作为一个“可选中、可调整大小的矢量对象”浮动在图片上方。
  - **笔迹物理锁定**：它们通过将 Canvas 锁定或在 Fabric.js 级别中，强制为新生成的笔画对象赋予属性：
    ```javascript
    path.set({
        selectable: false,    // 绝对不可选中
        evented: false,       // 不响应任何鼠标悬停、点击等交互事件
        hasControls: false,   // 不显示控制点和边界框
        hoverCursor: 'default' // 鼠标经过时保持常规光标，不显示移动抓手
    });
    ```
  - **图层物理隔离**：所有的 Stroke 笔迹只作为底层的像素叠加层（Overlay）存在，用户在任何模式下均可以点击并直接操作底部的图片，而掩膜图层完全“透明且不可触碰”，从而 100% 杜绝误触。

#### 2️⃣ Figma / Photopea (修饰键双态无感融合范式)
*   **参考规格**：
    在成熟的图像编辑软件中，**“拖拽/平移（Pan）”和“绘制/画笔（Brush）”根本不需要两个独立的按钮来切来切去**。它们是通过高频易用的**修饰键（Modifiers）**实现瞬时无感切换的：
  - **默认画笔态**：激活消除或扩图画笔时，左键在画布上拖拽永远执行“涂抹掩膜/绘制”动作。
  - **空格键 / 中键 Pan 状态**：在任何状态下（哪怕当前正在涂抹），只要用户**按住键盘空格键（Space）或鼠标中键**，光标会瞬时变为“小手抓手（grab）”，此时左键拖拽立即执行“画布平移/图片拖拽”；一旦释放空格键/中键，光标和功能瞬间秒回画笔状态。
  - **滚轮自适应缩放**：按住 `Ctrl` 键滚动滑轮，或直接使用触控板双指缩放，画布将**以当前鼠标光标所在的位置为几何物理中心进行缩放**，而不是简单粗暴地以画布几何中心点缩放，极大提升局部微调的体验。

### 6.3 后续版本改良升级交互规格设计 (The Refined UX Spec)

为了让 Outpaint v2 拥有不亚于 Canva 与 Photopea 的高品质交互，后续前端升级开发需强制遵守以下交互规格：

#### 🛠️ 1. 彻底移除手动的“拖拽模式”与“涂抹模式”按钮切换
- **无状态设计**：在右侧操作区，废除多余的“切换拖动/切换涂抹”模式切换器。
- **融合操作流**：
  - **涂抹行为**：激活“画笔消除”后，鼠标在**图片对象内部**左键拖动，即直接连续绘制红色掩膜（且松开鼠标后绝对不弹回拖动模式，画笔按钮保持常亮，直至用户点选其他主工具）。
  - **平移行为**：按住键盘 `Space` (空格键) 或是鼠标 `中键 (Wheel Click)`，光标变更为 `grab`。此时拖拽左键，即可进行整个 Fabric 视口画布的平移（Pan）。
  - **图片微调行为**：如果商户要微调图片在画布中的位置，只要鼠标左键在**图片外围的空白灰色背景区**拖拽，或者直接拖动图片的边界拉伸控制点，即可触发移动/缩放图片，完美规避了与画笔的冲突，不需要专门切换模式。

#### 🛠️ 2. 物理死锁掩膜笔画对象，实现 100% 误触物理防御
- **笔迹防卫**：在 Fabric.js 的 `path:created` 事件中，针对创建出来的笔画 `path`，在将其存入队列的同时，强行设置锁死属性：
  ```javascript
  canvas.on('path:created', function(e) {
      const path = e.path;
      path.selectable = false;
      path.evented = false;
      path.hoverCursor = 'default';
      // 保持笔画在图片上方，但将事件响应层级完全穿透
  });
  ```
  这直接从底层逻辑上物理锁死了画笔路径，用户再也不可能用鼠标选中或拖走它。

#### 🛠️ 3. 实现笔画级别高精度 Ctrl+Z 物理撤销队列
- **历史栈设计**：在 `State` 状态管理器中建立一个 `maskHistoryStack = []` 笔画撤销历史栈。
- **入栈机制**：每次触发 `path:created` 事件，将该 `path` 对象的引用 `push` 进 `maskHistoryStack`。
- **高精度撤销 (Undo)**：
  - 监听键盘全局 `Ctrl + Z` 事件。
  - 触发时，从 `maskHistoryStack` 中 `pop()` 出最近的一条笔画路径对象。
  - 调用 `canvas.remove(targetPath)` 并执行 `canvas.requestRenderAll()`，实现高精度无损物理级“撤销最后一笔笔迹”，极大提升画遮罩时的容错空间。
