1. 1. - # 产品需求文档 (PRD)：神灯AI·项目迁移穿梭机 (MagicLamp_AI_Project_Migration)

        > **代码仓库 (Repository)**：https://github.com/ala2017/MagicLamp-AI-Studio/tree/main/skills/MagicLamp_AI_projec_migration

        ## 1. 产品概述与核心价值

        ### 1.1 核心立项场景：中局突围与破局迁移

        本产品仅适用于“开发中（半成品）或已完成但面临重大技术调整的核心代码项目”。系统通过skill模式，解决项目在跨工具或跨模型迁移时的冷启动损耗。

        - **模型能力卡死场景**：项目遭遇深层内存泄漏、跨模块逻辑断层或未知底层 Bug，当前工具或模型触及推理天花板，必须无缝迁移至更高推理性能的环境。
        - **工具生态卡死场景**：当前宿主的 Agent 编排逻辑、本地索引深度或 MCP 插件权限无法满足攻坚任务，必须跨工具穿梭到其他更强大的运行时环境（包括但不限于 Antigravity, Hermes Agent 及最新主流 AI 开发工具）。

        ### 1.2 核心痛点

        中局破局场景下，项目存在大量复杂的半成品代码、冗余日志、中英文并存的需求变更与任务断点。由于市场主流工具的初始化机制缺乏对大体积垃圾文件、缓存及冗余日志的自动规避能力，在更换工具或重置会话时，盲目读盘会瞬间造成海量 Token 吞噬（即“高昂看盘费”），且历史长对话噪音极易导致新模型出现语义失真。

        ### 1.3 产品定位与生态位（充分利用·替代优化·无损补充）

        本产品是一套标准的 Claude Code Skill 规范扩展，定位为跨环境穿梭时的“冷启动燃料与行为约束器”：

        - **充分利用**：当目标工具自带低能耗本地初始化与索引机制时，系统终止全量扫描，直接承接并配合其原生索引能力。
        - **替代优化**：当目标工具缺乏项目初始化感知、盲目全量读盘或不具备自动初始化功能时，系统强行介入，通过物理层隔离与专属初始化 SOP 脚本进行替代驱动。
        - **无损补充**：针对工具原生无法感知的业务盲区（中英双语 PRD/Task 任务断点冲突及控制台报错行），输出绝对纯净的上下文补充，确保新模型实现靶向攻坚。

        ### 1.4 核心工作流定义（双流程：Snapshot / Resume）

        本产品有且仅有两条流程，由项目根目录是否已存在 `DEHYDRATED_CONTEXT.md` 决定。任何触发先由本地确定性脚本（非大模型）执行零 Token 路由探测，再决定走向：

        - **流程路由（零 Token 判定）**：探测 `DEHYDRATED_CONTEXT.md` 是否存在、是否陈旧（generated_at > 14 天）、git 是否漂移（当前脏文件数较快照记录 +5 以上），输出 `recommended_flow`：`snapshot` / `resume` / `resume_then_resnapshot`。用户显式键入 `/migrate` 时无条件走 Snapshot（强制重新快照）。

        - **流程 A：Snapshot（快照迁移）**：当目录无交接书，或用户要求“迁移项目 / 生成快照 / 换工具继续”时触发。
          1. **强制第一步——先提示切换低成本模型**：快照全程为确定性脚本，无须高性能模型推理。系统必须首先提示用户切换至低成本模型（Gemini Flash / DeepSeek-Coder·V3 / Claude 3.5 Haiku）再执行快照，以节省 Token；待快照完成后再切换高性能模型续接。
          2. 依次执行模块一（物理截流）→ 模块二（双语断点 + 立体时钟）→ 模块六（覆盖审计 + CODE_MAP 补全，门控不达标时触发）→ 模块三（脱水产出 + 凭证洗涤 + 缓存固化）→ 模块五（目标工具适配）→ 模块四（降级向导 + `[TERMINATE_SESSION]`），并指引用户复制交接书、切换模型/工具、开启新会话。

        - **流程 B：Resume（续接开发）**：当目录已有 `DEHYDRATED_CONTEXT.md`，或用户要求“继续开发 / 理解项目 / 了解项目状态 / 恢复进度 / 阅读交接书”时触发。
          1. **当前工具环境适配**：读取交接书第 6 节 `TARGET_TOOL_INIT`，执行当前工具的初始化驱动（模块五能力），信任既有 Stereo-Clock 排序，不重跑断点仲裁。
          2. **只读交接书重建上下文**：按 STACK → 真理源排序 → 原子断点 → git 高亮区 → 屏蔽区顺序消化 `DEHYDRATED_CONTEXT.md`，不盲读源码；若存在 `[CRITICAL_CONFUSED_ZONE]`，由当前高性能模型结合代码实况裁决。
          3. **漂移处置**：路由为 `resume` 直接续接；路由为 `resume_then_resnapshot` 时先恢复理解，再建议用户重新 `/migrate` 刷新快照。Resume 流程不写入 `[TERMINATE_SESSION]`。

        > 说明：本节为对模块四「降级向导」时序的补充——Snapshot 场景下，低成本模型提示前置为强制第一步；模块四原有的“产出快照后打印降级向导”仍在流程 A 末尾保留，用于引导新环境冷启动。

        ## 2. 详细功能需求 (Functional Requirements)

        ### 2.1 模块一：针对开发中项目的物理截流与多生态屏蔽（Shadow Ignorance）

        - **需求背景**：半成品项目积累了大量旧工具缓存、编译产物和长日志。必须在新工具执行初始化前，强行在物理层建立隔离带，阻止流氓读盘。
        - **系统执行逻辑**：
          1. **零 Token 依赖嗅探**：禁止调用大模型通读文件。系统必须直接调用标准本地目录读取工具（如 glob / find），通过特征文件（如 package.json $\rightarrow$ Node.js；requirements.txt $\rightarrow$ Python；go.mod $\rightarrow$ Go）锁定当前技术栈。
          2. **强制追加全生态 AI 隔离规则**：系统在注入隔离规则时，不仅修改 `.gitignore`，必须同时同步创建或强行覆写目标 AI 工具的专属忽略文件（包括但不限于 `.cursorignore`, `.aiderignore`, `.claudeignore`）。拦截对象包括：
             - .aider*（Aider 历史长对话缓存）
             - .cursor/ 与 .claude/（宿主工具本地状态与快照）
             - *.log（运行日志，严禁 AI 扫描长日志，必须人工截取报错）
             - .chroma/ 与 .qdrant/（本地向量库临时索引）
          3. **覆写冲突与物理隔离兜底**：若本地已存在 `.gitignore` 等文件，系统必须采用增量追加（Append）模式，且必须将补丁强行置于文件最顶部。若检测到目标环境具有无视忽略文件强行扫描的特征，系统应放弃在原目录交接，直接在系统临时目录（`tmp/`）建立一个**物理硬链接影子工程**，将受污染的缓存目录、大日志物理剔除后，再将影子工程移交给目标工具初始化。

        ### 2.2 模块二：中英文双语多源检索与混合状态立体熔断（锁定半成品状态）

        - **需求背景**：项目开发中局存在中英文档记载的需求变动、未完成的任务（Task）以及控制台报错。必须在迁移前完成业务与技术断点的逻辑闭环。
        - **系统执行逻辑**：
          1. **双语模糊路径匹配**：系统必须并行执行中英文双轨路径的模糊检索与正则匹配，防止上下文失真：
             - **需求源**：PRD* / *需求* / *功能* / *设计说明*/*Requirement*/ /*Function*/ /*Design Description*/
             - **基础与历史源**：README.md / CHANGELOG.md / *更新日志* / *版本*
             - **任务进度源**：TASK* / TODO* / *任务* / *进度*
          2. **去噪提炼规范**：系统读取文档后，严禁使用 Markdown 代码块复制原文。必须将其转化为纯粹的符号化原子断点：
             - *状态词统一对齐*：Done / 已完成 / Merged 统一抽象为 [DONE]；In Progress / 进行中 / Doing 统一抽象为 [ACTIVE_BREAKPOINT]。
             - *铁律强制锚定*：仅允许提取包含 MUST、REQUIRED、严禁、必须 的关键业务边界。
          3. **立体时钟分布式熔断机制**：系统获取所有目标文档的状态。当不同语言或路径的文档存在逻辑冲突，且物理时间戳（mtime）差值 $\ge$ 24小时，以时间轴上最新修改的文档作为最高真理源。若物理时间戳差值 $< 24$ 小时，系统必须升级为以下**混合状态立体兜底流水线**：
             - **方案 A（标准 Git 逻辑时钟）**：若检测到 `.git` 存在且文件处于 `Clean` 状态，调用 `git log -n 1 --pretty=format:%ci -- [file_path]` 提取精准的提交时间链作为真理源。
             - **方案 B（虚拟物理时钟与语义熵分析）**：若项目处于完全无 Git 环境（如本地临时目录或精简 Docker 容器），系统尝试读取底层文件系统日志（如 USN Journal / FSEvents）的 `ctime`。若系统日志不可信，则通过本地词法分析统计文档中 `TODO`、`FIXME` 及未闭环 Markdown 列表（`- [ ]`）的数量。业务断点标记更多且包含最新报错特征行的文档，判定为活跃现场，赋予更高冲突权重。
             - **方案 C（暂存区差异捕获）**：若检测到 `.git` 存在但文件处于 `Modified`、`Staged` 或 `Untracked` 等“脏代码”状态，系统执行 `git diff` 并调用 `git hash-object [file_path]` 强制生成临时虚拟 Object ID。若未提交的增量中包含当前控制台报错对应的特征或最新需求变更关键词，则强制判定此“脏代码状态”为最高真理源。
          4. **非阻塞延迟仲裁干预**：若同时触发了方案 B 且冲突文档的语义熵完全对等、无法自动仲裁时，系统**严禁在终端原地挂起死锁**。系统必须转为非阻塞模式，终止后续文件写入，并在生成的 `DEHYDRATED_CONTEXT.md` 最顶部强行开辟一个独立的标记区块 `[CRITICAL_CONFUSED_ZONE]`（困惑缓冲区），自动摘录冲突的原子断点行，将仲裁权延后交给新环境下的高性能模型去结合代码现状进行逻辑推理。

        ### 2.3 模块三：无损产物输出、视界截断与提示词缓存强固化

        - **需求背景**：交接资产的大小、结构必须与物理工程事实对齐，以最大化触发服务商的云端缓存机制，锁定成本。

        - **系统执行逻辑**：

          1. **动态令牌预算模型 (Dynamic Token Budgeting)**：交付文档 `DEHYDRATED_CONTEXT.md` 采用动态令牌预算制，体积边界由项目依赖拓扑复杂度动态决定，其极限表达式定义如下：

             $$T_{\text{budget}} = f(\text{DependencyTreeDepth}) \times C_{\text{info\_density}}$$

             核心约束指标为：**“严禁包含任何非必要的重复代码块（No Duplicate Code-blocks）”**。

          2. **绝对锚定与视界截断规范**：代码描述必须全量采用路径加符号的绝对锚定（如 `src/services/pay.ts -> login() -> line 89`），禁止任何源码段落的复制。同时引入“项目根目录相对化”和“第三方库剪枝”：凡是涉及 `node_modules`、`venv` 等外部依赖的路径，严禁展开，统一截断为符号占位符（如 `[External_Dep] -> React -> useState`），防止由于深层拓扑污染导致文本对抗性膨胀。

          3. **日志去噪过滤规范**：针对控制台报错，系统必须过滤掉冗长的 Stack Trace，仅保留【报错类型、报错信息、属于业务代码的第一层堆栈行号】。

          4. **全管道凭证洗涤（Secrets Laundering Pipeline）**：在将任何断点、代码描述、报错日志写入 `DEHYDRATED_CONTEXT.md` 之前，必须内置基于正则与高熵扫描的本地脱敏引擎。一旦匹配到符合 API Key、密码、Token 特征的字符串（包括未完工代码、注释、暂存区残留），强制替换为 `[REDACTED_SECRET_HASH_SHA256]`，从源头上杜绝敏感资产进入脱水文档。

          5. **提示词缓存命中的条件稳定性规范 (Prompt Caching Stability)**：

             - *静态头部锁死与零变异填充（Zero-Variance Locking）*：`DEHYDRATED_CONTEXT.md` 必须输出高度固定的结构化头部（Schema 不变），确保在前几次交互中被云端判定为静态块（Static Block）进行全量缓存。时间戳、动态增量等易变元数据**必须移至文档最尾部（非缓存敏感区）**，确保前置核心区块字符流在字符级别完全静态。
             - *增量控流*：系统必须彻底剥离历史聊天垃圾，使新会话后续的增量交互差量完美承接在缓存区块之后，直接命中 90% 账单折扣门槛。

        ### 2.4 模块四：成本控制与模型降级向导（阻断高能耗长对话）

        - **需求背景**：旧会话上下文已极度膨胀，必须在产出状态快照后立即强制切断当前会话，并引导用户在新工具环境中使用低成本、高性价比模型进行开局看盘。
        - **系统执行逻辑**：
          1. **输出中断规范**：生成状态快照后，系统必须在最后一条指令中加入显式终止符 [TERMINATE_SESSION]，直接闭环会话，阻断大模型继续输出总结性废话。
          2. **降级向导打印**：系统必须输出标准的格式化 Markdown 向导，强制打印推荐的低成本冷启动分析模型清单：
             - *Gemini 1.5 Flash*：用于超大上下文的低成本本地分析。
             - *DeepSeek-Coder / V3*：用于高性价比的代码生成与推理。
             - *Claude 3.5 Haiku*：用于快速逻辑初筛与梳理。

        ### 2.5 模块五：目标工具初始化与调用规则自适应适配（新环境自适应驱动）

        - **需求背景**：针对不同软件初始化机制不同、工具调用规则不同的痛点，系统必须在迁移报告结尾输出直接能被目标工具完美解析的专属初始化规范与调用行为约束（Sub-ruleset）。
        - **自适应适配矩阵**：以下为示例：包括不限于这些，市场主流的AI ide工具，和AI agent ，cli等支持 AI skill规范的工作环境都是潜在的迁移方向。
          1. **针对 Antigravity 目标环境**：
             - *初始化驱动*：若本地初始化未被触发，系统必须输出显式指令引导执行其本地 Tree-sitter 和 uv 虚拟环境同步（ag sync）；若本地已构建，则直接声明底层全量读取本地索引。
             - *工具调用规约*：强制注入行为约束铁律——“充分利用其原子任务管理能力，严禁直接修改物理文件，必须通过创建 Task 节点 (ag task create) 来驱动代码变更”。
          2. **针对 Hermes Agent 目标环境**：
             - *初始化驱动*：指示并充分利用其本地增量向量索引与 WASM 符号分析能力。
             - *工具调用规约*：强制注入并规范其特有的 thought -> action -> observation 闭环调用流，并补充显式声明的临时文件写入权限。
          3. **针对 通用 IDE / Standard MCP 目标环境**：
             - *初始化驱动*：由于通用环境无自动初始化，系统必须强制提示用户使用标准的终端命令执行 npm install 依赖一致性自检，防止环境依赖缺失。
             - *工具调用规约*：规范其使用标准的本地文件读写 API（如 read_file, write_file），严格锁死 Token 边界。

        ### 2.6 模块六：文档覆盖审计与代码地图补全（Coverage Gate & CODE_MAP）

        - **需求背景**：模块二的原子断点全部来自 `.md`/`.txt` 文档，只能回答“在做什么（What）”，无法回答“在哪个文件（Where）”。当项目 PRD/任务文档对真实源码树覆盖不足时，新环境模型拿到断点清单后仍被迫全量翻找 `src/`，触发探索风暴，迁移效率与 Token 节省双双劣化。因此交接书必须以**确定性、零 Token、不复制源码**的方式补上代码锚点。
        - **系统执行逻辑**：
          1. **零 Token 覆盖审计（确定性、仓库接地真值）**：在写入 `DEHYDRATED_CONTEXT.md` 之前，系统先用本地脚本（`scripts/build_project_map.py`）扫描真实源码树与全部文档，输出两个客观指标：
             - **漏报率 omission%**：真实源码文件（按文件名）从未被任何文档提及的比例。
             - **漂移率 drift%**：文档引用、但磁盘上已不存在的代码路径比例（死链）。
             - 该审计直接以仓库现实为基准，不依赖快照自身，杜绝循环依赖。
          2. **门控触发条件**：当 `omission% > 15` 或 `drift% > 20` 时，判定文档地图不达标，自动进入补全；否则跳过，保持纯文档快照的字节稳定，绝不浪费 Token。
          3. **免费层补全（ast，零 Token）**：用 `ast`（Python）/ 语言无关正则回退（JS/TS/Go/Rust 等）抽取“真实文件树 + 每文件签名（类名、函数名、首行 docstring）”，注入交接书 `## 3b. CODE_MAP` 节。**严禁复制任何源码体，仅落地签名锚点**，与模块三“绝对锚定、禁止源码复制”一脉相承。
          4. **可选廉价模型层（仅喂签名，一次性批处理）**：`--describe` 模式下，仅把已抽取的签名（绝不含文件正文）批量喂给最低成本模型（DeepSeek-Chat / GPT-4o-mini），为每个文件生成一句话责任说明。此步与开发期高性能模型解耦，用最节省方式完成，可整体关闭（`--no-code-map`）。
          5. **缓存一致性**：`## 3b. CODE_MAP` 对给定仓库状态完全确定，跨同项目重跑字节级一致，落在模块三“零变异静态块”契约之内；仅在门控触发时出现，文档完备项目保持 1–6 节原始布局。

        ## 3. 安全防线与验收标准

        ### 3.1 安全指标

        - **状态锁定**：系统必须自动读取 git status 摘要并作为“高亮观察区”写入交接书，确保新模型执行精准的靶向增量阅读，防止覆盖本地未提交的代码。
        - **凭证隔离与多层深度洗涤**：在扫描项目文档、.env 模板及局部代码注释时，系统严禁将任何明文密码、API Key 写入交接文档。除了基础占位符提示外，必须执行全管道凭证洗涤（Secrets Laundering），若发现疑似残留，一律使用 SHA256 动态哈希占位抹除。

        ### 3.2 验收标准 (Acceptance Criteria)

        1. **斜杠命令响应**：在包含历史代码和开发中半成品项目的终端键入 /migrate，系统能正确唤醒该 Skill，并完整执行物理层截流与逻辑层脱水流水线。
        2. **多层级混合时钟与非阻塞熔断验证**：当文档存在矛盾且修改时间差在 24 小时以内时，系统必须准确触发混合状态立体兜底。在无 Git 环境且语义熵对等的极限情况下，系统能准确进行非阻塞降级，生成 `[CRITICAL_CONFUSED_ZONE]` 困惑缓冲区并安全终止，拒绝原地死锁。
        3. **场景与工具自适应验证**：
           - *优秀工具环境*：交接书能够精准配合其本地索引，不重复读盘，只增量补充双语业务断点与当前报错行。
           - *粗暴/无自动初始化工具环境*：交接书能够强制替代输出初始化 SOP 命令与工具调用行为约束规则，完美矫正其流氓读盘行为。
        4. **文档覆盖门控与代码地图补全验证**：当项目文档对真实源码树覆盖不足（漏报率 > 15% 或漂移率 > 20%）时，系统必须自动以零 Token 的 `ast` 抽取注入 `## 3b. CODE_MAP`（仅签名、无源码体），使补全后漏报率降至接近 0；文档完备项目则跳过补全、不破坏 1–6 节静态布局。补全段须跨同项目重跑字节级一致。
