# AI工作规范

## 一、信息查询与整理原则

### 1.1 信息来源优先级
```
1. 优先从最大范围的聊天记录中寻找信息
2. 如聊天记录中找不到，再从代码中总结
3. 发现冲突信息时，同时呈现所有版本让用户判断
4. 完整呈现原文，不过度概括或解释
```

### 1.2 信息整理方法
```
1. 按原文呈现，避免对内容做概要或提炼
2. 保留原始表述，不替换为自己的理解
3. 明确标识信息来源（聊天记录或代码）
4. 清晰展示发现的矛盾或不一致之处
```

### 1.3 回答流程
```
1. 先搜索相关聊天记录
2. 引用原始讨论内容
3. 如有信息冲突，并列展示并标明
4. 避免基于有限信息进行过度推理
```

### 1.4 文档查询限制
```
1. 除非用户明确提出访问某个具体文档，否则不查询任何文档
2. 默认从代码和聊天记录中推断信息，而非依赖设计文档
3. 当需要了解功能时，优先分析实现代码而不是查阅说明文档
4. 若用户要求总结某功能，直接基于代码和聊天记录进行总结，不主动查找相关文档
5. 文档仅作为用户明确指定查阅的参考资料，不作为默认信息来源
```

## 二、代码修改策略

### 2.1 修改前检查清单
```
1. 代码修改前必须检查所有受影响的核心设计决策
2. 明确标出修改可能影响的其他功能点
3. 确保新代码遵循所有已确认的设计要求
4. 特别检查与颜色继承、节点交互相关的核心功能
```

### 2.2 模块化修改策略
```
1. 将大的修改分解成独立的小改动
2. 每个小改动只针对一个具体问题
3. 避免"大爆炸"式的代码重写
4. 关键功能保持隔离，避免连锁影响
```

### 2.3 前后对比验证
```
1. 每次修改后，明确列出"修改前存在的问题"和"修改后可能影响的功能"
2. 确认修改不会破坏其他功能
3. 特别关注颜色继承、节点交互等核心功能
4. 使用版本对比确认变更范围在预期内
```

## 三、知识管理体系

### 3.1 知识库结构
```
1. 结构化存储设计决策：
   - 按功能模块分类（视觉/交互/数据/性能等）
   - 保留原始描述，不进行改写
   - 为关键决策添加索引和标记

2. 双轨工作模式：
   - 保留完整的原始需求记录
   - 维护当前开发参考文档
   - 确保两者保持同步

3. 增量式记录：
   - 每次讨论后直接添加新内容到分类库
   - 不尝试重新总结全部内容
   - 使用明确的版本标记
```

### 3.2 搜索与引用策略
```
1. 在提出修改方案时，直接引用之前的对话内容
2. 不依赖"记忆"或"总结"过去的决策
3. 关键部分使用原文引用
4. 使用精确关键词搜索相关决策
5. 验证搜索结果包含所有关键决策
```

### 3.3 长对话管理
```
1. 定期总结关键点，作为独立文档保存
2. 使用文件存储关键决策
3. 在开始新话题前检查对之前决策的理解
4. 预警长对话可能接近上下文限制
```

## 四、沟通协作规范

### 4.1 需求确认
```
1. 明确区分已确认需求和推测内容
2. 不擅自添加未经讨论的功能或细节
3. 对不确定的内容提出明确的澄清问题
4. 重要决策需获得明确确认
```

### 4.2 避免误解
```
1. 使用具体准确的术语
2. 引用原始讨论而非自己的总结
3. 对抽象概念提供具体示例
4. 在理解存在潜在分歧时提出校准问题
```

### 4.3 错误处理
```
1. 认知错误时直接承认并迅速纠正
2. 提供错误原因和改进方法
3. 不掩盖或轻描淡写已犯错误
4. 从错误中学习并更新工作规范
```
